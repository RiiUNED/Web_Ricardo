Laboratorio M1T1 - Troubleshooting de un servicio Linux

SIGTERM, SIGKILL y reinicios con systemd

Investigación de un servicio Linux que no responde correctamente a una solicitud de parada y que se reinicia automáticamente después de una terminación forzada.

service-troubleshooting systemd journalctl linux-signals service-lifecycle

>_ Relevancia Operativa

Este laboratorio demuestra la capacidad práctica para investigar incidencias en servicios Linux mediante el análisis de su comportamiento, los registros de systemd y las señales utilizadas durante su ciclo de vida.

También demuestra la capacidad para identificar la causa de una terminación incorrecta, relacionar el comportamiento de un proceso con la configuración del servicio y verificar la corrección aplicada mediante herramientas como systemctl, journalctl y pgrep, incluyendo el análisis de políticas de reinicio como Restart=on-failure.

Contexto del incidente

  • Sistema: Ubuntu Server 24.04 LTS
  • Servicio: t1m01.service
  • Aplicación: proceso Python ejecutado como servicio mediante systemd

Durante las pruebas se observan dos comportamientos anómalos:

  • systemctl stop no consigue detener el servicio dentro del tiempo esperado.
  • La terminación forzada del proceso mediante kill -9 provoca que systemd inicie automáticamente una nueva instancia con un PID diferente.
