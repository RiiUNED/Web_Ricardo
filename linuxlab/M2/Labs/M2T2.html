Laboratorio M2T2 - Acceso privilegiado inesperado

Diagnóstico y corrección de una configuración de sudoers mediante la auditoría de privilegios autorizados, la comprobación de una escalada de privilegios y la aplicación del principio de mínimos privilegios.

privilege-escalation sudoers-audit least-privilege access-control

>_ Relevancia Operativa

Auditoría de privilegios con sudo -l e id para detectar una configuración que permite ejecutar código como root.

Reproducción controlada de la escalada, corrección de la regla con visudo y validación de que se bloquea el acceso no autorizado sin perder la capacidad de ejecutar el respaldo permitido.

Contexto del incidente

Una auditoría de privilegios comprueba que el usuario M2user2 tiene autorización para ejecutar el script de respaldo /usr/local/bin/M2app-backup.sh como root. Sin embargo, la regla definida en /etc/sudoers.d/M2backup también permite ejecutar /usr/bin/python3 con argumentos arbitrarios y sin solicitar contraseña, lo que posibilita ejecutar código con privilegios de superusuario más allá de la tarea autorizada.

Incidencias observadas

Auditoría de privilegios

M2user2@ubuntu-lab:~$ whoami && id
M2user2
uid=1002(M2user2) gid=1004(M2user2) groups=1004(M2user2),1001(M2shared),1005(M2extra2)
M2user2@ubuntu-lab:~$ sudo -l
Matching Defaults entries for M2user2 on ubuntu-lab:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin, use_pty

User M2user2 may run the following commands on ubuntu-lab:
    (root) NOPASSWD: /usr/bin/python3 *, /usr/local/bin/M2app-backup.sh

Interpretación

La auditoría de sudo -l muestra los comandos que M2user2 tiene autorizados para ejecutar como root sin introducir contraseña.
Entre ellos figuran el script de respaldo M2app-backup.sh y el intérprete Python 3, cuya autorización incluye un comodín * para los argumentos.

Investigación y causa raíz

Ejecución de Python como administrador

M2user2@ubuntu-lab:~$ sudo /usr/bin/python3 -c "import os; os.execl('/bin/sh', 'sh', '-p')"

Comprobación de identidad

# whoami && id
root
uid=0(root) gid=0(root) groups=0(root)

Interpretación

M2user2, una cuenta ordinaria, puede obtener una shell privilegiada. La regla de sudoers permite ejecutar Python con argumentos arbitrarios como root.
No se está explotando un error de Python ni del kernel: se está utilizando una autorización administrativa demasiado amplia.

Correcciones aplicadas

ricardo@ubuntu-lab:~$ sudo visudo -f /etc/sudoers.d/M2backup
M2user2 ALL=(root) NOPASSWD: /usr/local/bin/M2app-backup.sh

Interpretación

La regla corregida elimina la autorización genérica del intérprete Python y mantiene únicamente la ejecución del script de respaldo como root, sin solicitar contraseña. De este modo, se restringen los privilegios concedidos a M2user2 a la tarea de mantenimiento prevista, aplicando el principio de mínimos privilegios.

Verificaciones posteriores

Matriz de verificación

Prueba de validación Comando de ejecución Resultado esperado
Auditoría de restricciones sudo -l Desaparición de la autorización genérica de Python.
Bloqueo de escalada sudo /usr/bin/python3 -c "import os; os.execl('/bin/sh', 'sh', '-p')" Ejecución denegada por falta de autorización en sudoers.
Acceso operativo legítimo sudo /usr/local/bin/M2app-backup.sh Ejecución correcta del script de respaldo autorizado.
