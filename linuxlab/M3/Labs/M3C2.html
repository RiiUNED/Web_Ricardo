Laboratorio M3C2 - Gestión de volúmenes lógicos con LVM

Objetivos

Preparación del laboratorio

Para trabajar en los experimentos de este laboratorio, se añadirá un segundo disco secundario.

Estado inicial de la máquina virtual

ricardo@ubuntu-lab:~$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
NAME                       SIZE TYPE FSTYPE      MOUNTPOINTS
sda                         30G disk
├─sda1                       1M part
├─sda2                       2G part ext4        /boot
└─sda3                      28G part LVM2_member
  └─ubuntu--vg-ubuntu--lv   14G lvm  ext4        /
sdb                          5G disk
└─sdb1                       5G part ext4        /mnt/m3data
sr0                       1024M rom

Entorno de pruebas

ricardo@ubuntu-lab:~$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
NAME                       SIZE TYPE FSTYPE      MOUNTPOINTS
sda                         30G disk
├─sda1                       1M part
├─sda2                       2G part ext4        /boot
└─sda3                      28G part LVM2_member
  └─ubuntu--vg-ubuntu--lv   14G lvm  ext4        /
sdb                          5G disk
└─sdb1                       5G part ext4        /mnt/m3data
sdc                          5G disk
sr0                       1024M rom

Interpretación

Dispositivo Tamaño Tipo Estado actual
sda 30 GiB disk Disco virtual principal. Contiene Ubuntu Server.
sda1 1 MiB part Partición de 1 MiB sin sistema de archivos ni punto de montaje identificado.
sda2 2 GiB part Partición ext4 montada en /boot.
sda3 28 GiB part Partición que contiene el volumen físico de LVM.
ubuntu--vg-ubuntu--lv 14 GiB lvm Volumen lógico ext4 montado en /. Contiene el sistema raíz de Ubuntu.
sdb 5 GiB disk Disco virtual secundario destinado a M3C2. Contiene la partición sdb1.
sdb1 5 GiB part Partición con sistema de archivos ext4, montada en /mnt/m3data. Procede del laboratorio M3C1.
sdc 5 GiB disk Segundo disco virtual secundario, recién añadido para M3C2. Sin particiones, sistema de archivos ni punto de montaje.
sr0 1024 MiB rom Dispositivo óptico virtual. Unidad de CD/DVD de VirtualBox.

Observación
El disco /dev/sdb conserva la estructura de particiones y el sistema de archivos ext4 creados en el laboratorio M3C1. Su partición /dev/sdb1 se encuentra actualmente montada en /mnt/m3data.

Como parte de la preparación del entorno, se desmontará /dev/sdb1 para liberar el dispositivo y permitir su inicialización como Volumen Físico (PV) de LVM mediante pvcreate /dev/sdb.

Desmontaje de la partición /dev/sdb1 de /mnt/m3data 

ricardo@ubuntu-lab:~$ sudo umount /mnt/m3data
ricardo@ubuntu-lab:~$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
NAME                       SIZE TYPE FSTYPE      MOUNTPOINTS
sda                         30G disk
├─sda1                       1M part
├─sda2                       2G part ext4        /boot
└─sda3                      28G part LVM2_member
  └─ubuntu--vg-ubuntu--lv   14G lvm  ext4        /
sdb                          5G disk
└─sdb1                       5G part ext4
sdc                          5G disk
sr0                       1024M rom

El comando umount se ha ejecutado correctamente. La partición /dev/sdb1 conserva su sistema de archivos ext4, pero ya no presenta ningún punto de montaje. El disco queda liberado para su posterior inicialización como Volumen Físico (PV) de LVM.

El segundo disco, /dev/sdc, también está disponible y sin particiones ni sistemas de archivos. Ambos dispositivos se encuentran preparados para continuar con la configuración de LVM.

Observación
Desmontar no elimina los datos ni el sistema de archivos. Simplemente libera la partición para las operaciones posteriores de M3C2.

Experimento 1 - Inicialización de Volúmenes Físicos (PV) y creación de Grupos de Volúmenes (VG)

Objetivo

Inicializar /dev/sdb como Volumen Físico (PV), crear el Grupo de Volúmenes (VG) vg_lab y verificar mediante las herramientas de administración de LVM su correcta configuración y la capacidad de almacenamiento disponible.

Intervención

Estado inicial

ricardo@ubuntu-lab:~$ lsblk
NAME                      MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda                         8:0    0   30G  0 disk
├─sda1                      8:1    0    1M  0 part
├─sda2                      8:2    0    2G  0 part /boot
└─sda3                      8:3    0   28G  0 part
  └─ubuntu--vg-ubuntu--lv 252:0    0   14G  0 lvm  /
sdb                         8:16   0    5G  0 disk
└─sdb1                      8:17   0    5G  0 part
sdc                         8:32   0    5G  0 disk
sr0                        11:0    1 1024M  1 rom

1. Inicialización de /dev/sdb como Volumen Físico (PV) 

ricardo@ubuntu-lab:~$ sudo pvcreate /dev/sdb
  Cannot use /dev/sdb: device is partitioned
ricardo@ubuntu-lab:~$ sudo pvcreate /dev/sdb1
WARNING: ext4 signature detected on /dev/sdb1 at offset 1080. Wipe it? [y/n]: y
  Wiping ext4 signature on /dev/sdb1.
  Physical volume "/dev/sdb1" successfully created.

2. Creación del Grupo de Volúmenes (VG) vg_lab usando /dev/sdb1 

ricardo@ubuntu-lab:~$ sudo vgcreate vg_lab /dev/sdb1
  Volume group "vg_lab" successfully created

3. Comprobaciones

ricardo@ubuntu-lab:~$ sudo pvs
  PV         VG        Fmt  Attr PSize   PFree
  /dev/sda3  ubuntu-vg lvm2 a--  <28.00g 14.00g

ricardo@ubuntu-lab:~$ sudo vgs

  ubuntu-vg   1   1   0 wz--n- <28.00g 14.00g
  vg_lab      1   0   0 wz--n-  <5.00g <5.00g
ricardo@ubuntu-lab:~$ sudo vgdisplay vg_lab
  --- Volume group ---

  System ID
  Format                lvm2
  Metadata Areas        1
  Metadata Sequence No  1
  VG Access             read/write
  VG Status             resizable
  MAX LV                0

  Max PV                0

  VG Size               <5.00 GiB

  VG UUID               PCAdhh-Snsc-eQNV-QI2u-9ofE-FPvM-LEssyZ

Intepretación

La primera inicialización mediante pvcreate /dev/sdb no fue posible porque el dispositivo contenía una tabla de particiones. Se utilizó /dev/sdb1, que fue inicializado correctamente como Volumen Físico (PV). Durante el proceso, LVM detectó la firma ext4 existente y solicitó autorización para eliminarla, permitiendo sustituir la estructura anterior por metadata de LVM.

A continuación, se creó el Grupo de Volúmenes vg_lab, que incorpora un único PV. Las comprobaciones mediante pvs, vgs y vgdisplay confirman su correcta configuración: dispone de una capacidad inferior a 5 GiB, distribuida en 1279 extensiones físicas (PE) de 4 MiB cada una.

Observación
El grupo todavía no contiene volúmenes lógicos (LV), por lo que ninguna extensión está asignada. Toda su capacidad permanece disponible para crear volúmenes lógicos o incorporar nuevos dispositivos físicos.

Experimento 2 - Creación de Volúmenes Lógicos (LV) y sistemas de archivos

Objetivo

Crear un volumen lógico de 1 GB (lv_datos) dentro del grupo de volúmenes vg_lab, formatearlo con Ext4 y montarlo en el sistema de archivos. Se comprobará su configuración y capacidad mediante las herramientas de inspección de LVM y del sistema, relacionando la ruta del dispositivo lógico con la estructura de dispositivos que gestiona el kernel de Linux.

Intervención

1. Comprobación del espacio libre disponible en vg_lb 

ricardo@ubuntu-lab:~$ sudo vgs vg_lab
  VG     #PV #LV #SN Attr   VSize  VFree
  vg_lab   1   0   0 wz--n- <5.00g <5.00g

2. Creación de lv_datos

ricardo@ubuntu-lab:~$ sudo lvcreate -n lv_datos -L 1G vg_lab
  Logical volume "lv_datos" created.

3. Formateo con ext4

ricardo@ubuntu-lab:~$ sudo mkfs.ext4 /dev/vg_lab/lv_datos
mke2fs 1.47.0 (5-Feb-2023)
Creating filesystem with 262144 4k blocks and 65536 inodes
Filesystem UUID: cda74acd-f71e-4591-aa5b-df16385d5eb0

        32768, 98304, 163840, 229376

Allocating group tables: done

Creating journal (8192 blocks): done
Writing superblocks and filesystem accounting information: done

4. Montaje del volumen lógico en /mnt/m3data

ricardo@ubuntu-lab:~$ sudo mount /dev/vg_lab/lv_datos /mnt/m3data
ricardo@ubuntu-lab:~$ df -Th /mnt/m3data/
Filesystem                  Type  Size  Used Avail Use% Mounted on
/dev/mapper/vg_lab-lv_datos ext4  974M   24K  907M   1% /mnt/m3data

4. Inspección

Interpretación

El grupo de volúmenes disponía de capacidad suficiente para crear lv_datos, que se ha generado con el tamaño solicitado de 1 GiB y se ha formateado correctamente con Ext4. La salida de df -Th confirma que el sistema de archivos está montado en /mnt/m3data, con una capacidad utilizable de 974 MiB.

LVM presenta el volumen lógico mediante la ruta /dev/vg_lab/lv_datos, que corresponde al dispositivo /dev/mapper/vg_lab-lv_datos. Ambas rutas identifican el mismo dispositivo de bloques gestionado por el kernel. La inspección con lvs y lvdisplay confirma que el volumen está disponible, tiene un tamaño de 1 GiB y cuenta con un segmento asignado.

Experimento 3 - Extensión del Volumen Lçogico y del sistema de archivos en claiente

Objetivo

Ampliar en caliente el volumen lógico lv_datos, incorporando un segundo disco virtual al grupo de volúmenes vg_lab y asignando 1,5 GiB adicionales al volumen.
Se comprobará que LVM permite ampliar el dispositivo lógico y redimensionar simultáneamente el sistema de archivos ext4, manteniendo el volumen montado y accesible durante la operación.

Preparación

1. Estado del volumen lógico

ricardo@ubuntu-lab:~$ sudo lvs -o lv_name,vg_name,lv_size,lv_attr,devices
  LV        VG        LSize   Attr       Devices
  ubuntu-lv ubuntu-vg <14.00g -wi-ao---- /dev/sda3(0)
  lv_datos  vg_lab      1.00g -wi-ao---- /dev/sdb1(0)

2. Estado del montaje

ricardo@ubuntu-lab:~$ findmnt /mnt/m3data
TARGET      SOURCE                      FSTYPE OPTIONS
/mnt/m3data /dev/mapper/vg_lab-lv_datos ext4   rw,relatime

3. Escritura de prueba

ricardo@ubuntu-lab:~$ sudo touch /mnt/m3data/m3c2.txt
ricardo@ubuntu-lab:~$ ls -l /mnt/m3data/
total 16
drwx------ 2 root root 16384 Nov 11 12:02 lost+found
-rw-r--r-- 1 root root     0 Nov 11 13:20 m3c2.txt

Interpretación

Las comprobaciones confirman que lv_datos está activo, tiene un tamaño de 1 GiB y utiliza /dev/sdb1 como soporte físico. El sistema de archivos ext4 permanece montado en /mnt/m3data con opciones de lectura y escritura rw.
La creación de m3c2.txt verifica que el volumen admite escrituras. Por tanto, el entorno está preparado para ampliar el volumen lógico y su sistema de archivos sin desmontarlos.

Intervención

1. Inicialización del segundo disco virtual /dev/sdc como Volumen Físico 

ricardo@ubuntu-lab:~$ sudo pvcreate /dev/sdc
  Physical volume "/dev/sdc" successfully created.

2. Extensión de vg_lab incorporando /dev/sdc 

ricardo@ubuntu-lab:~$ sudo vgextend vg_lab /dev/sdc
  Volume group "vg_lab" successfully extended

3. Ampliación y redimensión del sistema de archivos de vg_lab 

ricardo@ubuntu-lab:~$ sudo lvextend -r -L +1.5G /dev/vg_lab/lv_datos
  Size of logical volume vg_lab/lv_datos changed from 1.00 GiB (256 extents) to 2.50 GiB (640 extents).
  Logical volume vg_lab/lv_datos successfully resized.
resize2fs 1.47.0 (5-Feb-2023)
Filesystem at /dev/mapper/vg_lab-lv_datos is mounted on /mnt/m3data; on-line resizing required
old_desc_blocks = 1, new_desc_blocks = 1
The filesystem on /dev/mapper/vg_lab-lv_datos is now 655360 (4k) blocks long.

Comprobación

ricardo@ubuntu-lab:~$ df -Th /mnt/m3data/
Filesystem                  Type  Size  Used Avail Use% Mounted on
/dev/mapper/vg_lab-lv_datos ext4  2.5G   24K  2.4G   1% /mnt/m3data

Interpretación

La incorporación de /dev/sdc como segundo volumen físico permitió ampliar el grupo de volúmenes vg_lab sin modificar el volumen lógico existente. Mediante lvextend se asignaron 1,5 GiB adicionales a lv_datos, pasando de 1 GiB a 2,5 GiB (640 extensiones lógicas de 4 MiB).

La opción -r ejecutó también el redimensionamiento en línea del sistema de archivos ext4 mediante resize2fs. La salida confirma que la operación se realizó con el sistema de archivos montado. Finalmente, df -Th verifica que la capacidad del punto de montaje /mnt/m3data ha aumentado a 2,5 GiB sin desmontar el volumen ni interrumpir su acceso.
